## 2. 姿态、状态索引与协方差

采用 Hamilton 四元数，`R = R(q)` 将全局 G 系向量变换到 IMU I 系：

```text
v_I = R v_G
R_true = R_hat Exp(delta_theta_G)
delta_x = [delta_theta_G, delta_p_G, delta_v_G, delta_bg_I, delta_ba_I]
block offsets = [0, 3, 6, 9, 12], dimension = 15
```

右乘误差在 **全局系** 表达，不再保留“右乘但误差在 IMU 系”的矛盾注释。对应：

```text
R_next = Exp(-omega_I * dt) R
v_dot = R^T (a_m - ba) + gravity_G
F(theta,bg) = R^T
F(p,v) = I
F(v,theta) = skew(R^T (a_m-ba))
F(v,ba) = -R^T
```

`quatIntegrate` 是通用右侧指数增量助手，并非直接表示 `G -> I` 的物理陀螺传播。传播使用相邻 IMU 样本、子步中点姿态和加速度；状态转移为二阶近似，过程噪声用保持半正定的梯形近似。它不是精确连续系统离散化。

相机外参 `qIC` 满足 `v_C=R_IC v_I`，故 `qGC=qIC*qGI`。相机原点 `pGC=pGI+R_GI^T pIC`。增广 Jacobian 的姿态块为单位阵，位置对姿态块为 `skew(R_GI^T pIC)`，位置对位置块位于第 3 列，不是第 1 列。

Joseph 协方差更新保留；求解使用 LDLT 直接作用于所需右端项。姿态注入后对 IMU 与每个相机块应用右 Jacobian 重置。视觉测量在同一线性化点堆叠，必要时 QR 压缩后只做一次注入，避免分批使用过期残差。

## 3. 时间调度与线程所有权

`SensorTimeline` 按采集时间处理 IMU 和其他观测。默认水位为最新 IMU 时间减 50 ms，可通过 `filter.reorderWindowNs` 调整。这里是有界等待／重排序，不是历史状态回滚。

在观测时间位于 IMU 两个端点之间时，插值得到该时刻 IMU，并传播到该时刻，再执行量测。等时刻 IMU 先于观测；相机克隆的状态时间等于图像时间。超过已提交时间水位后才到达的观测会被明确拒绝，尾部没有 IMU 覆盖的观测不会被外推处理。

时间队列上限：4096 个 IMU、256 个非 IMU 观测；采集入口队列另有 8192 项上限。被保留图像总数限制为 8 张，单图大小另有限制。输入队列在短锁内交换到本地，然后释放锁执行算法。滤波、初始化、磁校准、视觉跟踪和时间队列均由单一融合线程拥有。所有快照的读写使用同一快照锁。

状态输出增加 `late`、`overflow`、`invalid`、`unbracketed`、`admissionDrops`、`rejectedImages`、`queued` 和 `visualUpdates`。这些计数区分队列拒绝、无法对齐和实际视觉更新。异常输入／过大 IMU 间隔会使会话暂停并保留错误信息，必须重置或重新开始，而不是带着坏状态继续计算。

## 4. 轨迹生命周期与视觉

特征删除列表由调用方持有，更新函数不再清空同一个列表。丢失或被窗口裁剪消费的特征无论三角化／门限是否成功，都从活动轨迹中移除。存活匹配先标记，再消费丢失轨迹，最后用释放出的名额补点，避免满额上一帧阻止本帧替换。

相机克隆被删除前先处理引用它的轨迹。前端仍在跟踪的同一 ID 可开始新的观测段，但不会重复使用已消费观测。

KLT 中参考窗口固定不动，目标估计只在相邻金字塔层之间放大一次；参考坐标始终从原图坐标按层缩放。梯度和残差窗口对齐，使用浮点双线性采样、收敛与纹理检查、前后向一致性检查。FAST-9 连续弧段检查不再使用错误的快速排除条件。

三角化在无畸变归一化观测上进行；投影残差和 Jacobian 使用同一个带畸变模型。视差由全局坐标系中的两条射线求得，避免把不同相机坐标系中的视线直接点乘。

## 5. 可选网络服务

默认 `GVIO_WITH_SERVER=OFF`、运行配置 `server.enabled=false`。算法验证与证书、端口解耦。启用网络后，失败的证书加载／监听初始化会传播为 `start()==false`。

TLS 配置由服务器实现对象持有，所有连接销毁后才释放。连接、socket、TLS 和 HTTP/2 会话使用明确所有权；应用数据仅通过 `mbedtls_ssl_write` 发送，部分写入和 `WANT_READ/WANT_WRITE` 重试期间保持缓冲地址与剩余长度稳定。

HEADERS/DATA 的 END_STREAM 标记决定请求体何时完成。SSE 从首次响应即使用 data provider；暂时无数据时返回 DEFERRED 而不是 EOF。每个流独立持有缓冲和偏移，事件使用 `data:` 行与空行结尾。控制回调只投递命令，不执行服务器线程的同步停止。

HTTP `stop` 暂停并清空会话，保留网络控制接口；`start` 清空状态后恢复新会话；`reset` 清空状态但不改变暂停状态；`magcal` 开始收集校准样本。返回 `queued` 只表示命令已投递，不等于状态更新已经执行。外部 `FusionEngine::stop()` 才终止线程及服务器。

当前为本机开发服务器，不具备应用层访问认证；不要把这些修复解释成生产级公网服务加固。
